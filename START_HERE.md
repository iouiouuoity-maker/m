# ErrorMap V8 — запуск

Это полная версия с отдельными учётными записями ученика и учителя, общей SQLite-базой, заданиями и очередью email-отчётов. Установка пакетов не нужна; требуется Python 3.12 или новее.

## Запустить на компьютере

Распакуйте архив. Откройте терминал в папке проекта:

```sh
python3 server/start.py
```

Откройте **http://localhost:8000**. Это новая главная страница с переключателем **Оқушы / Мұғалім** и гостевым входом. Выберите вход учителя для первого запуска. В терминале появится одноразовый для первоначальной настройки код `First-time teacher setup token`. Во вкладке **Teacher setup** введите этот код, имя, логин и пароль (не менее 10 символов). После регистрации первого учителя эта вкладка отключается. Код не является паролем для последующих входов.

1. Учитель: **Classes → New class**. Передайте код класса ученикам.
2. Ученик: **Join a class**. Введите код класса и создайте свой логин и пароль.
3. Учитель: **Question bank**. Создавайте вопросы или копируйте один из 240 готовых. Собственные вопросы можно редактировать и архивировать.
4. Учитель: **Assignments**. Выберите класс, название и вопросы. Сохраните черновик. Его можно открыть кнопкой **Edit**, изменить название и набор вопросов. Затем нажмите **Publish**.
5. Ученик: **My assignments → Start**. Ответы сохраняются на сервере после каждого выбора. Перед сдачей можно проверить и изменить ответы. После **Submit result** результат окончательный.
6. Учитель: **Results**. Откройте подробности ответа ученика. Для обновления списка нажмите **Try again**.

English / Қазақша / Русский переключаются вверху. Тексты английских упражнений остаются на английском. Сообщения проверки ввода сервером могут отображаться по-английски.

## Подключить почту позже

В **Settings → Report email** учитель указывает адрес получателя. Он необязателен при регистрации.

Для реальной автоматической отправки настройте SMTP на сервере. Скопируйте `.env.example` в `.env` и заполните значения, полученные у вашего почтового провайдера:

```dotenv
SMTP_HOST=smtp.your-provider.example
SMTP_PORT=587
SMTP_SSL=0
SMTP_FROM=reports@your-domain.example
SMTP_USER=your-smtp-login
SMTP_PASSWORD=your-smtp-password
```

Перезапустите сервер. Для SMTP с implicit TLS используйте `SMTP_SSL=1` и порт вашего провайдера, обычно 465. Для остальных соединений всегда применяется STARTTLS. Обычная отправка без TLS не поддерживается.

Очередь проверяется каждые 30 секунд. Результаты, накопившиеся до подключения почты, также отправятся на указанный адрес. После пяти неудач статус станет `failed`; исправьте настройки и нажмите **Retry pending emails**. Успешно отправленные отчёты повторно не ставятся в очередь. В редком случае сбоя между приёмом письма SMTP-сервером и записью статуса возможен дубликат. `sent` означает, что SMTP-сервер принял письмо, а не гарантирует доставку во входящие.

**Реальная доставка на ваш адрес ещё не проверена: адрес и SMTP-доступ не предоставлены.** Автоматические тесты проверяют очередь и состав письма с тестовой заменой SMTP.

## Разместить онлайн

**GitHub Pages не запускает Python и базу данных.** Workflow Pages в этом архиве публикует только прежнюю автономную версию. Для кабинетов нужен сервер с Python или Docker и постоянным диском. Код можно хранить в GitHub, а выполнять на отдельном сервере.

Для сервера за HTTPS reverse proxy:

```sh
python3 server/start.py --host 0.0.0.0 --port 8000
```

Задайте `ERRORMAP_ORIGIN=https://ваш-домен` и `ERRORMAP_SECURE_COOKIE=1`. Прокси должен сохранять исходный `Host`; публичный доступ — только через HTTPS. База находится в `data/classroom.sqlite3` или каталоге `ERRORMAP_DATA`. Подключите постоянный диск. Одна копия приложения с одним фоновым отправителем почты; несколько worker-процессов без отдельной координации очереди не поддерживаются.

Docker:

```sh
docker build -t errormap .
docker run --env-file .env -p 8000:8000 -v errormap-data:/data errormap
```

Первоначальный код настройки будет в логах запуска. Учитель создаётся один раз. Настоящие пароли и SMTP-ключи не должны попадать в GitHub. Перед сменой сервера сохраните базу; резервную копию делайте SQLite backup API или при остановленном приложении, чтобы учесть WAL. Потеря диска без резервной копии означает потерю данных.

## Что входит и что разделено

- `/` и `/index.html`: новая публичная главная с интерактивным обзором шести навыков.
- `/classroom/student.html` и `/classroom/teacher.html`: отдельные входы и серверные кабинеты. У ученика — обзор, задания и карта на основе последних сданных ответов по каждому правилу. У учителя — обзор класса, банк, редактор заданий и результаты.
- `/workspace.html`: существующий автономный учебный цикл из восьми страниц, 240 вопросов и 24 правил. Ссылка **Independent practice** ведёт туда. Он по-прежнему хранит учебный цикл в браузере; эти данные автоматически не переносятся в серверные кабинеты и не отправляются по почте.
- В серверном задании оцениваются выбранные учителем вопросы. Шкала — число правильных ответов, без заявления о валидированной оценке освоения языка.
- Задание хранит копию вопросов. Последующее изменение вопроса не меняет уже созданное задание или результаты. Для новой редакции создайте новое задание. Опубликованное задание не редактируется задним числом.
- Одна сдача на одно задание. Для повторной проверки учитель создаёт новое задание.
- Общая база ограничивает ученика его классом и собственными попытками. Пароли хешируются scrypt, сессии хранятся на сервере и истекают через 12 часов; cookie HttpOnly / SameSite. Публичной регистрации учителей нет.
- Это учебный инструмент, не защищённая экзаменационная система: исходный банк автономной версии с ключами доступен в статических файлах. Новые учительские вопросы и их ключи выдаются только учителю; ученик получает ответы после сдачи.
- Восстановление забытого пароля через email, школьный SSO, управление несколькими учителями и удаление учётных записей через интерфейс пока не реализованы. Сохраняйте доступ к учётной записи учителя.

## Проверить код

```sh
node tests/check.cjs
python3 tests/classroom_test.py
```

Интеграционный тест использует временную базу и локальный HTTP-сервер. Проверяет вход, роли, разделение классов, редактирование вопросов, неизменность опубликованных заданий, перемешивание вариантов, сохранение и сдачу ответов, очередь писем и смену пароля. Реальные почтовые сообщения тест не отправляет.

## Проверка интерфейса

`node tests/experience_test.cjs` проверяет пустые состояния, метрики по реальным данным, выбор последних ответов по времени сдачи и экранирование имён. Главная и обе страницы входа просмотрены в браузере на настольном размере. Полный мобильный просмотр и ручной проход авторизованных кабинетов в браузере не выполнялись; доступы и сдача проверены HTTP-интеграционными тестами.

Для GitHub + Vercel используйте **VERCEL_START.md**. Гостевой вход открывает учебные инструменты; это не вход в чужую учётную запись.
